# Change Log

## Unreleased

- No more background rebuild of the simulation model on save (`xheep.rebuildModelOnSave` is gone). Build runs mcu-gen
  only when the platform is missing or older than its configuration; Run also builds the model only when it is missing
  or older than the RTL. A platform generated or a model built by hand is used as it is, so mcu-gen and the model
  builds can also run outside the extension. A platform generated by hand shows as **manual** in the status bar and is
  never regenerated by the extension until you pick a configuration. The Memory Map then shows it as generated (from
  its C header).
- The run button in the status bar tells the simulation model, built apart from the app: a green ▶ when it is ready,
  a red ✗ when its build failed, a 🔧 when it needs a build; Run builds it first then. A model built by hand
  (`make verilator-build`) counts. The app name next to it tells the app's build, also after a `make app` by hand.
  Opening a file of an app makes it the active one, which Run builds and runs.
- **X-HEEP tab** in the bottom panel: the app's UART next to the log of everything the extension runs (mcu-gen, model
  and app builds, simulator, OpenOCD). Tasks still run in the terminal, and **Show Log** opens the tab.

## 0.7.0

- Tested with X-HEEP [528381f](https://github.com/x-heep/x-heep/commit/528381f5014d972511079820f1e0c36a222cfeb1).

## 0.6.0

- **X-ALP**: open an X-ALP clone, or start a software project with **New X-ALP Software Project**. Build and Run
  in simulation, from the SPM or the DRAM (status bar), the Memory Map view, and the platform editor with X-ALP's
  knobs (cache geometry and SPM size, DRAM, peripherals). Debug is wired up, waiting for X-ALP's JTAG debugging to
  work in simulation. FPGA and flash stay X-HEEP's only.
- No longer takes an X-ALP repo for X-HEEP (it vendors X-HEEP's generator, but builds and runs differently).
- A project whose path has spaces or `? * + [ ] ( ) | ^ $ \` is refused when created, and gets a clear error
  instead of a failed build: make and the platforms' CMake cannot handle them.

## 0.5.0

- **New Hardware Project**: a new repo from gr-heep, to extend X-HEEP with your own hardware, renamed after
  the folder (files, SystemVerilog modules, fusesoc core, C header).
- Works in gr-heep and its forks (X-HEEP vendored in `hw/vendor/x-heep`): platform generation, simulation models and
  bitstreams through the project's Makefile, configuration from `config/`.
- **Memory Map**: Copy Address copies the C define (`UART_START_ADDRESS + UART_CTRL_REG_OFFSET`), not the hex value.
  The map also reads the older X-HEEP that gr-heep vendors.

## 0.4.0

- Works with VS Code 1.92 and later (was 1.140), e.g. the older VS Code of Ubuntu's packages.

### Hardware development

- The simulation model is rebuilt in the background when an RTL file in `hw/` or `tb/` is saved, and a run never
  uses a model older than the RTL (`xheep.rebuildModelOnSave`).
- Verilator and Questasim errors of the model build go to the Problems panel, with warnings only outside vendored IPs.
- **Open Waveform**: the `waveform.fst` of the last Verilator run, in Surfer or GTKWave.
- SystemVerilog with the Verible extension: lint, go to definition across modules (from a `verible.filelist` of the
  model's files), and formatting on save as X-HEEP's `util/format-verible` does, only in the folders it covers
  (`xheep.formatRtlOnSave`).
- **Memory Map** view: RAM, address regions, peripherals and their registers and fields, with addresses to copy.
- App regression in the Testing view: the apps on the active platform's simulation model, skipping those X-HEEP's
  app test leaves out.

### Environment

- Check Environment and Set Up Tools share one list of checks: the report and its **Fix…** button always agree.
- Set Up Tools also handles verible (the version X-HEEP uses) and offers X-HEEP's Verilator version when another one
  is installed.
- With the environment OK, **Change a Tool…** switches a working tool (another toolchain, Verilator, the container).
- A disconnected FPGA board is a note, not an environment problem: simulation-only is the norm.

## 0.0.1 (preview)

- Applications view: your apps and the X-HEEP examples, new app and new file.
- Run modes: Simulation (Verilator/Questasim), FPGA JTAG debug (EPFL Programmer, on-board BSCAN, Digilent HS2), FPGA flash.
- Automatic platform generation (mcu-gen) and simulation model build when the configuration changes.
- Platform configurations kept in your project (`configs/*.py`), with a template from X-HEEP.
- Fast incremental builds and direct Verilator runs; UART output in its own panel.
- VS Code debugger (breakpoints, stepping) over OpenOCD, in simulation and on FPGA.
- Software-only projects with X-HEEP as a git submodule or a linked clone.
- Environment check with one-click fixes.
